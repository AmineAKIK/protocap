# WS-07 — Dependency and supply-chain hygiene evidence

**Status:** CLOSED

## Scope

WS-07 reviewed dependency necessity and freshness policy, transitive warning origins, production/build dependency separation, lockfile integrity, npm install-script policy, Dependabot coverage, GitHub Actions pinning, Docker dependency strategy, and whether cleanup could be achieved without destabilising the release.

## Findings and remediation

### 1. Development/build advisories had drifted into the lockfile

An isolated audit of the pre-fix graph reproduced three transitive advisories in the development/build dependency graph:

- `browserslist` — high severity;
- `fast-uri` — high severity;
- `postcss-selector-parser` — low severity.

The production-only graph remained at zero vulnerabilities.

PR #107 refreshed only compatible transitive lockfile resolutions using the ranges already declared by existing dependencies. No direct dependency version was changed. The resulting graph reports zero vulnerabilities for both the full install and the production-only install.

The corrected transitive resolutions include:

- `browserslist` 4.28.2 → 4.28.8;
- `fast-uri` 3.1.5 → 3.1.7;
- `postcss-selector-parser` 6.1.2 → 6.1.4;
- associated Browserslist data packages refreshed within existing compatible ranges.

### 2. npm install-script approval was implicit

`npm ci` reported that the `esbuild@0.25.12` postinstall script was not yet covered by an explicit `allowScripts` declaration.

PR #107 recorded the reviewed install script as an exact version-pinned approval:

```json
"allowScripts": {
  "esbuild@0.25.12": true
}
```

A clean reinstall after that change removed the npm `allow-scripts` warning.

### 3. Dependency advisories were checked too late in CI

The first version of PR #107 placed dependency audits after Docker and browser checks. Review identified that a future advisory would therefore fail only after the most expensive CI work had already run.

The final PR moves both dependency audits immediately after `npm ci`:

1. full graph: `npm audit --audit-level=high`;
2. production graph: `npm audit --omit=dev`.

The exact-head Quality Gate proved that both audits pass in fail-fast position before Docker and Playwright work.

### 4. Two deprecation warnings remain upstream build-tool residue

A clean development install still emits:

- `source-map@0.8.0-beta.0` deprecation;
- `glob@11.1.0` old-version/deprecation warning.

Both trace through the PWA build chain `vite-plugin-pwa -> workbox-build@7.4.1`. They are development/build-only dependencies and are not present in the production runtime install.

They are retained intentionally for this release because removing them would require an unrelated PWA dependency migration without evidence of a runtime or release defect. The repository documents these warnings explicitly rather than suppressing or misrepresenting them as clean output.
